# Оценка качества ассистента и контроля диалогов (C3-08)

Все результаты получены через runtime-сервис (`IntelligenceService` — тот же, что обслуживает HTTP/UI). KEY-файлы организаторов передаются только неизмененному `selfcheck.py` в отдельном процессе. Синтетические наборы написаны командой (Клауд третий), это **не** скрытые данные организаторов.

Среда: Linux-контейнер, Python 3.12.3, без сетевого AI-ключа (режим `local_limited`, путь `deterministic`). Коммит с evidence — см. `docs/status/CLAUDE_3_MUSTAFA.md`.

## Команды

```sh
uv run python -m glassflow.modules.intelligence.evaluation open      # 18 вопросов + 8 диалогов → selfcheck.py
uv run python -m glassflow.modules.intelligence.evaluation extended  # 96 синтетических кейсов
uv run python -m glassflow.modules.intelligence.evaluation holdout   # 36 holdout-кейсов
uv run python -m glassflow.modules.intelligence.evaluation perf      # локальные задержки
uv run python -m glassflow.modules.intelligence.evaluation live      # сетевой профиль ×3 (BLOCKED без ключа)
```

Evidence: `docs/ai/evidence/{open,extended,holdout,perf,live,gateway}/`.

## История и честность

- Расширенный набор: первый прогон 77/96. 18 «срабатываний» были ложными в самом оценщике (числа из названий позиций — «ZUNXIN 997», «лист 2750 × 1605», порог «от 100 шт», нормализованные «1200 мм» — не регистрировались как факты); 2 реальных дефекта движка: опечатка «сирое» и «За сколько дней…», принятое за вопрос о цене. Исправлено в движке и верификаторе; эталоны кейсов не менялись.
- Holdout: файл записан после настройки расширенного набора и до первого запуска; отчет первого прогона сохранен без изменений (`evidence/holdout/holdout_report_FIRST_RUN.json`). Дефекты: «4 полкодержателя» (количество перед названием), «бронза 8мм лист целиком» (бонус дословного имени перевешивал толщину), «а 8 мм?» (уточнение атрибута следующей репликой). После исправлений — 36/36, эталоны не менялись.
- Шаблонный прогон по всем позициям KB вскрыл хрупкость контроля диалогов: если менеджер пишет название зеркала без запятой, слово «лист» из названия формата ошибочно означало «цену листа». Исправлено устойчивым к пунктуации удалением названия.
- Политика неизвестной цены (после первого holdout): если запрошенная цена неизвестна (нет ставки за м², фацет/пескоструй и т. п. в фокусе вопроса), текст клиенту не содержит цифр — ни других цен, ни эха размеров; известная цена листа и расчет стекла остаются в рабочей карточке и предложении. Причина: правдивые, но не запрошенные числа в ответе на «неизвестную» цену читаются как утверждение цены. В holdout изменено ожидание H018 (раньше требовало 200 000 в тексте) — это явное продуктовое решение, а не подгонка; в отчете первого прогона ожидание сохранено как было.
- Добавлен отдельный сценарий цены кромки без размеров («Сколько стоит кромка на стекло 6 мм?» → 400 ₸/м по правилу r4; 8 мм → менеджер без чисел).
- Оба набора написаны тем же агентом, что и движок: возможна систематическая слепота к незнакомым формулировкам. Независимую проверку дадут закрытые 30 вопросов/10 диалогов (без KEY официальных баллов нет — T52) и ручная проверка интегратором.

## Ручная проверка смысла (T24 «не только числа»)

По `evidence/open/report.json`: в 18 ответах цена соответствует именно запрошенной позиции и базе (м², лист, розница/от 100 шт), расчеты показывают площадь и ставку, у вопросов без цены в KB (фацет, пескоструй, AB1020) нет чисел из 3+ цифр и есть передача менеджеру, правила (монтаж, оплата, скидка) процитированы из KB r1/r2/r7. Ответы 1–3 предложения; правила дополнены коротким предложением о возможности расчета.
