## Author comparison, not independent acceptance

Pinned baseline: `5648852d64189ffd7269c277002f6fbc40c8039a`. The comparison runs baseline
matching/local source and candidate in separate Python processes against the original
KB/materials. It uses nine disclosed author regressions, including two disclosed P0 cases;
it does not read the independent reviewer data. Thirty repeats per case measure local
response latency. Those measurements are software latency, not human labor savings.

| Metric | Baseline | Candidate |
|---|---:|---:|
| Correct requested status | 7/9 | 9/9 |
| Full correct totals retained | 4/4 | 4/4 |
| Unnecessary requests for manager-priced parameters | 2 | 0 |
| Explicit clarifications | 2 | 3 |
| Median local latency, ms | 14.24 | 15.70 |
| P95 local latency, ms | 16.40 | 17.57 |

The additional useful clarification is SKU choice; ambiguous decimal dimensions also now
produce an actual clarification status and missing-parameter card. Complete integer sizes
without a suffix keep the documented millimetre assumption; explicit centimetres/metres
normalize to the same total. These small timing differences are not a statistically
established speed claim. The independent examiner decides generalization and live AI quality.
Raw requests/answers/metrics: `n04-baseline.json` and `n04-candidate.json`.

N17 decision: the concrete measured extraction-related defect was an existing deterministic

## Review queue and KB preview

The shared central migration `0007_intelligence_reviews` follows
`0006_operational_documents` and calls the domain snippet. There is no separate database or
competing Alembic head. ORM tables are `intel_review_item` and `intel_manager_correction`.

Queue categories are distinct: `correct_policy`, `missing_parameter`, `kb_fact`,
`provider_error`, `verifier_reject`. Multiple real causes may coexist; a provider or verifier
failure is not turned into a KB fact gap. Assistant conversation turns enqueue atomically
with their stored response. Parent-accepted batch results use `outcome_reasons` metadata and
`record_accepted_batch_reviews(session,dataset_id,result)` in the coordinator result hook;
that helper consumes accepted metadata and never reruns an engine or invents a customer reply.

- `GET /api/v1/assistant/review-items?dataset_id=…&category=…&status=…`
- `POST /api/v1/assistant/review-items/{id}/resolve`: dataset_id, expected_version,
  resolved_by, resolution_note. A stale manager receives 409.
- `POST /api/v1/assistant/review-items/{id}/kb-preview`: dataset_id,
  expected_kb_version, proposed_content (exact JSON text). Returns proposed SHA/version,
  changed products/rules, affected stored quotes, mapping changes, current platform version,
  explicit-human-confirmation flag and existing apply endpoint.

Preview is read-only. Applying requires a separate explicit human action with exactly those
reviewed bytes to `POST /api/v1/datasets/{dataset_id}/kb`, multipart JSON file,
expected_version and Idempotency-Key. Existing platform rules enforce workspace-only edits
and version conflicts. A preview does not resolve a queue item or silently reprice a quote.

## Manager correction drafts

- `POST /api/v1/dialogs/corrections`: dataset_id, id, client, manager, kb_version.
- `GET /api/v1/dialogs/corrections?dataset_id=…` and `/{draft_id}?dataset_id=…`.

Only a unique known canonical applicable price produces `DRAFT_VERIFIED` with a product,
meaning/unit and exact evidence reference. An ambiguous product, unknown rate or uncertain
price meaning yields `NEEDS_REVIEW` and no answer/price. Already correct manager text yields
`NOT_NEEDED`. All statuses require human review. The original manager text, conversation,
quality results and confirmed quote history are not changed, and no message is sent.

### Shared QA quantity applicability

After a concrete author reproduction, dialog QA and N19 share a canonical bulk-scope
helper. A 3/99-unit order does not qualify for a 100-unit tariff: an unqualified wholesale
claim is ERROR with the applicable retail unit correction. At/above 100 units the known
bulk tariff applies. Unknown quantity plus an unqualified bulk claim stays NEEDS_REVIEW.
An explicit same-clause conditional tariff «от 100 шт» can be a true rate fact even for a
3-unit customer; it does not validate an incorrect total for those three units. A condition
below the catalogue minimum stays NEEDS_REVIEW. Thresholds are per-product KB facts, never
global allowed numbers. The existing commercial answer verifier was not loosened.

### Explicit identity and correction freshness

Unknown explicit alphanumeric SKUs, unlisted brands and incomplete generic hardware identity
cannot be silently replaced with a catalogue product. The rule derives identifiers and
distinguishing features from the current KB, not a fixed product/brand list. Known explicit
SKUs and a real differentiator such as small/large still resolve. Both local and model-first
paths enforce the rule; a follow-up cannot reuse the previous product/active quote after an
unknown identifier. Dialog QA also cannot use a different known product's price as evidence.

N19 single-draft reads return 409 STALE_KB_VERSION after a KB change. Lists project
`is_current=false` and `current_kb_version`, while retaining the original historical KB,
price and status. Stored JSON is unchanged; a new current request creates a new draft.
Consumers must treat a noncurrent row as history, not a currently applicable price.

An absent requested per-m² rate is a `kb_fact` gap even when a sheet price is known.
Known manager-priced mirror model rules remain `correct_policy`, separate from missing
catalogue rates and unknown parameters.
