Продолжай последовательно до завершения всей миссии; не останавливайся после первого merge, первого зеленого теста или стартового плана. Не проси «продолжай» на каждой фазе. Сохраняй checkpoint в docs/status/GPT_PRO_INTEGRATOR.md с commit, commands/results и следующим шагом. Жесткие ограничения сессии не обходятся обещанием фоновой бесконечной работы.

- Рекомендуемый порядок: Pro platform → C2 cutting → C3 intelligence → C1 UI. Учитывай фактические зависимости и сохраняй историю каждого автора.

- Python lock согласован с native deps, pnpm lock с фактическим клиентом; regenerate lock только при нужных dependency changes.
- Создай свежую БД и upgrade из foundation schema; проверь backups, миграции и persistence после перезапуска.

## I-03. Инварианты и официальная приемка

- Выполни unit, property, contract и transaction tests, затем реальные интеграционные сценарии. Не ослабляй критерии ради PASS.
- C2: геометрические границы, исключение для закаленного стекла, premium/defect, отсутствие повторов и пропусков, отмена с сохранением incumbent, locks и пять свободных кусков. Расширенный обычный расчет дает coverage ≥58,9523237% с допуском ТЗ.
- C3: точные позиции цены, округление и ревизии, неизвестные товары и mappings; 18 вопросов и 8 диалогов через runtime и selfcheck; минимум 60 дополнительных случаев, ≥95% корректных действий и ноль неподтвержденных коммерческих обещаний; критические случаи повторены три раза реальным профилем.
- Pro: стабильный baseline из 25 заявок, группировка клиентов, отсутствие утечки в модели, зафиксированная политика; семь метрик менеджеров с исходными строками и NULL; 50 проверенных покупателей, ≥30 в Астане и ≥5 категорий; пять карточек одного финального плана.
- Реальная SQLite concurrency: один резерв на один кусок, второй запрос получает 409; одинаковый ключ и тело повторяют прежний результат, другое тело конфликтует. Расход нельзя отменить обычным undo.
- Смена версии остатка или предложения делает связанные данные stale и блокирует подтверждение. Старый AI текст не подтверждает наличие.
- Измененные ID, строки, размеры и набор без метки проверяют отсутствие логики только для открытых данных. KEY доступны только оценщику.
- Исходные конкурсные данные не меняются рабочими действиями; одинаковые внешние ID разных dataset изолированы.
- Валидаторы организаторов неизменны и запускаются с UTF-8. Сохрани stdout, stderr, exit code и хеши выходов.

## I-04. Настоящие сквозные маршруты

1. Чистый импорт → рабочая копия → свободный русский запрос → уточнение → точная цена → реальный остаток → явный атомарный резерв.
2. Изменение размера, замера или цены → новая ревизия → сравнение площади, стоимости и NEW → подтверждение без молчаливой замены.
3. CRM: 25 заявок → уникальные клиенты → выбор адресата → локальная задача. Заказчик предложения остается прежним; задача по конкретному остатку становится stale при его занятости.
4. Свободные остатки → пять карточек → три покупателя каждой карточки → строгий экспорт. Смена плана требует повторной проверки.
5. Руководитель → семь показателей M1–M5 → исходные строки и знаменатели. Новые операционные события не переписывают историю.
6. Новый комплект → независимые jobs → частичный сбой → сохраненные готовые результаты → исправление → согласованные пять CSV.
7. Перезапуск, авария и отмена → сохраненная подтвержденная работа, валидный incumbent и interrupted status. Проверить целостность backup/restore.
8. Offline, AI 429 и timeout → локальное ядро работает, UI честно показывает ограничения, платный fallback при free_only отсутствует.

Проверь browser E2E с настоящим backend. Mocked tests выполняются отдельно и не подтверждают эти маршруты.

## I-05. Frozen Windows и AI для жюри

- Собери фактический PyInstaller onedir ZIP с frontend, шрифтами, миграциями, native solver и доверенными моделями. Запускай именно EXE, а не Python dev server.
- На чистом Windows без Python, Node и Docker: распаковка → README → приложение ≤5 минут. Если чистая машина недоступна, явно NOT RUN; установленное окружение автора не заменяет этот тест.
- Проверь freeze_support, отсутствие рекурсивного spawn, единственный экземпляр над БД, localhost/token/Origin/Host, свободный порт, /ready и корректное завершение.
- Данные сохраняются в `%LOCALAPPDATA%/GlassFlow`. Проверь persistence, backup/restore и upgrade. Повторный старт ≤30 секунд измеряется фактически.
- Gateway: HTTPS, холодный старт, срок токена и лимиты реально проверены с нового компьютера. Провайдерский секрет находится только на сервере; конкурсный токен ограничен и отзывной.
- Direct team profile протестирован с запасом квоты для batch run. Не публикуй ключи и не включай платный профиль без явного действия.
- Проверь фактическую доступность модели, результаты сетевой оценки и p95 по 30 запросам. Mock adapter и offline калькулятор не являются полной AI приемкой.
- При отсутствии ключа, hosting или чистой машины продолжай другие задачи и оставь точный release blocker.

## Разрешенное исключение: generated contracts

Каждый агент может регенерировать packages/contracts/openapi.json и packages/contracts/schema.d.ts стандартными командами репозитория после изменения DTO. Это явное исключение из файлового ownership: ручные правки generated файлов запрещены. Семантика domain DTO остается у domain-владельца, common DTO и ports — у Pro. При merge conflict интегратор заново генерирует оба файла из объединенных Python DTO, а не выбирает произвольную сторону. Не оставляй foundation OpenAPI snapshot gate сломанным после своих DTO changes.
