Исследование CRM, ассистента и контроля цен. 27.11.2026.
Это анализ перед проектированием, не реализация продукта. Источники не изменялись.

1. Состав данных
applications_open.csv: 700 заявок, 178 client_id, 5 менеджеров, 16 колонок, нет пропусков и повторов app_id. 298/700=42,5714% меток возврата. Дни от 0 до154.
База знаний: 47 уникальных товаров, в том числе25 материалов и22 позиции фурнитуры, 7 правил. У3 материалов нет цены за м², у11 нет цены целого листа. Отсутствующее нельзя автоматически вычислять по другой единице цены.
18 открытых вопросов,8 диалогов. Закрытый набор по PDF:30 вопросов,260 заявок без label,10 диалогов.

2. Существенное свойство официальной CRM-оценки
selfcheck.py сортирует эталон по ключу (-прошлых_заявок, жалоба, manager=='M4', дней_с_последнего_контакта). Результат: precision@25. Балл=10*clip((p-base)/(ref-base),0,1), если ref>base, иначе0.
Если собственный экспорт повторяет открытый эталонный алгоритм, использует тот же вход и порядок при равенстве ключей, то p=ref и балл10/10 при ref>base. Это содержательный воспроизводимый baseline, нет необходимости рисковать баллами ради более сложной модели без преимущества выше10. Не обещать закрытые10/10 без проверки актуального скрипта и tie ordering.
На открытых baseline выбрал20 возвращений из25, precision80%, официальный скрипт дал10/10. Файл analysis/crm/reference_picks.csv.

3. Исследование ML
Реализована только исследовательская L2-logistic regression на numpy, C=1, Newton/IRLS до60 итераций. Стандартизация и one-hot обучаются на train, неизвестные категории на test дают нули. ID клиента, ID заявки, день года, target в признаки НЕ включались.
Core: прошлых_заявок, дней_с_последнего_контакта, жалоба, manager, тип_клиента.
Full дополнительно: log1p(сумма_тг), доставка, скидка, ответ_через_мин, продано, группа_товара, канал.
10 random holdout с seed0..9:260 test/440 train. Средняя P@25 baseline70,8% (56–80), core78,8% (68–88), full74,8% (64–92).
10 group holdout с seed0..9:66 клиентов test, остальные train. Test239–271 заявка, mean253. Средняя P@25 baseline72,8% (56–80), core80,4% (68–96), full77,2% (60–88).
Temporal: последние260 заявок тест, предыдущие440 train: baseline72%, core76%, full72%.
Temporal с удалением обучающих строк, чей60-дневный горизонт не завершился к первому дню теста:172 train/260 test. baseline72%, core80%, full76%.
Эти варианты являются исследовательскими измерениями на одном маленьком учебном наборе. Повторные holdout перекрываются, это не независимые10 экспериментов, не доверительный интервал и не обещание результата hidden. Hyperparameter search не проводился. До выбора production модели нужен заранее замороженный протокол и дополнительная внешняя/будущая выборка.
Вывод: компактная интерпретируемая модель выглядит предпочтительнее добавления всех колонок, но для конкурса разумнее официальный baseline. CatBoost можно сравнить как challenger, не ставить по умолчанию только из-за сложности.

4. Ограничения синтетической истории
Поле прошлых_заявок во всех700 строках точно равно числу предыдущих заявок client_id по дням/ID. При этом recency совпал с интервалом между соседними заявками только у2 из522 повторных строк.
На431 заявке с наблюдаемым полным60-дневным окном следующая строка того же клиента в60 дней имеется у74,71%; label=1 у34,57%; согласие этих индикаторов46,87%. Это свойство учебных данных, а не основание заменять метку. Не реконструировать target из будущих строк, не показывать синтетическую последовательность как подтвержденную настоящую историю продаж.
Нет достоверной связи client_id с order_id/remnant_id. CRM знает5 общих групп товара, не точные material_id/размеры/потребности. Рекомендация остатка клиенту является гипотезой по группе и типу клиента; требуется уточнение размера и материала. Не выдавать ее за доказанную потребность.
Прогноз возврата не измеряет эффект сообщения. Дополнительные продажи от напоминаний можно подтвердить только сравнением contacted/control в пилоте; propensity(return) не равна uplift(contact).
На260 заявках требуется25 разных app_id, не25 уникальных клиентов. В реальном outreach нужна дедупликация client_id и частотные ограничения; конкурсный экспорт должен соответствовать своему контракту.

5. Ассистент: рекомендуемая схема
Свободный текст -> извлечение намерения/товара/единицы/размеров -> разрешение ID каталога -> структурированный доступ к KB -> детерминированный расчет -> короткий русский ответ с указанием основания. LLM может понимать вариативный язык, но цена и арифметика только из функций; при неоднозначности уточнение. Для47 товаров не нужна отдельная сложная векторная инфраструктура: точный индекс, словарь синонимов и fuzzy search с порогом, LLM только выбор кандидата или clarification. Один сервис цен для ответа клиенту и контроля менеджеров.
Раздельные ветки цены за м², целого листа, розницы и цены от100 шт. Заказ100 шт vs99 проверяется отдельно. Формат зеркала влияет на SKU/ставку. Размеры в мм; площадь=w*h/1000000. Предварительный расчет заканчивается подтверждением менеджером; не обещать наличие/сроки.
Ключевой нюанс: materials.csv mirror-4=9500 тг/м² для оценки экономии. KB: зеркало2750×1605=9500, зеркало3210×2250=11500. В складе нет origin формата листа. Не присваивать остаткам mirror-4 цену11500 произвольно; для оценки экономии/карточек использовать materials, для коммерческого расчета KB и уточнение варианта.
Листовая цена не обязана равняться цене м²*площади. Например2750×1605*9500/1e6=41930,625, а отдельная цена листа24000; это разные прайсовые позиции, их нельзя автоматически исправлять или смешивать.
Три рифленых материала8 мм имеют только цену листа. Отсутствующая цена за м² не выводится без утвержденной площади/правила.
Для евро-кромки4 мм=300/м,6 мм=400/м; количество обрабатываемых сторон нужно уточнить, если не задано. Фацет и другие толщины — менеджеру. МодельAB1012 отсутствует; ценыAB1001–AB1044 не заданы. Монтаж не выполняется, оплата на сайте не принимается, скидки не обещаются.
Приложенный unknown-check использует regex и не является полной проверкой выдумок. Числа из размеров или кодов могут ошибочно трактоваться как цена; не оптимизировать ответы под regex в ущерб содержанию. Жюри вручную проверяет5 ответов.
Данные/CSV/запрос клиента являются данными, не инструкциями системе; попытка изменить прайс в запросе должна игнорироваться.

8. Проверки для будущей реализации
Строгое разделение обучения и inference; запрет target на входе модели; group/time splits и60-дневное созревание labels; воспроизводимые seed/manifest; экспорт всех id ровно один раз;25 уникальных app_id; работа без target; никакого подтягивания закрытых ключей.
Для ассистента:100% каталожных цен и единиц; размеры со знаками×/x/на, мм/см/м; неоднозначный вариант зеркала;99/100шт; нулевая/отрицательная площадь; отсутствие цены; unknown item; опечатка; запрос скидки/монтажа/срока/наличия; injection; ошибка LLM/недоступность сети.
