# Проверка сокомандником на другом ноутбуке

Ноутбук сокомандника подходит. Нужен человек, который ещё не проходил этот сценарий.
Разработчик наблюдает и записывает затруднения, но не объясняет, куда нажимать.
Windows 10 пригодна для предварительной проверки. Windows 11 указана в ТЗ:
её самостоятельный запуск отмечается отдельно, только после фактической проверки.
Устанавливать Python, Node или среду разработки для запуска EXE не требуется.

## Первый запуск и заказ

1. Получите новый ZIP рабочей сборки и запишите его имя и SHA256 из сопроводительного отчёта.
2. Распакуйте всю папку. Откройте `НАЧАТЬ ЗДЕСЬ.txt`, затем `GlassFlow.exe`.
3. Самостоятельно импортируйте учебный ZIP и создайте рабочую копию.
4. Введите запрос: «Стекло 6 мм прозрачное 45 см × 370 мм, 2 штуки,
   евро-кромка по всем сторонам». Ожидается **3 976,00 ₸**.
5. Измените количество на `0 штук`, затем на `1,5 штуки`. Система должна
   попросить уточнение; подтвердить предыдущий расчёт с этими параметрами нельзя.
6. Исправьте количество на две штуки. Найдите остаток и его место хранения,
   подтвердите предложение, зарезервируйте, создайте напоминание.
7. Перезапустите приложение и найдите сохранённые заказ и напоминание.
8. Попросите второго менеджера зарезервировать тот же кусок. Второго резерва быть не должно.
9. Передайте заказ складу и подтвердите расход. Повтор команды не должен списать кусок снова.
10. Создайте резервную копию в настройках; восстанавливайте её только в отдельной тестовой базе.

Запишите ОС, имя сборки, время начала/конца, выполненные шаги, фактический результат,
скриншот проблемы и каждую подсказку наблюдателя. Если потребовалась подсказка,
самостоятельный шаг ещё не принят. Нельзя записывать автоматический браузерный тест
как проверку новым человеком. Не вводите реальные персональные данные клиентов.

## Десять пар трудозамеров

Это отдельная проверка эффективности, а не скорость первого знакомства.
Сначала дайте оператору освоить работу. Подготовьте десять разных типичных задач
с одинаковыми для обеих методик входами и критериями правильного результата.
Заранее сохраните исходные файлы и их хеши. Не выбирайте задачи по выгодному результату.

1. Откройте «Рабочее место → Экономика → Трудозамеры», создайте протокол
   с наблюдателем и точными определениями начала и конца операции.
2. Для каждой пары укажите одну задачу, её вход и оператора. Один и тот же человек
   выполняет её вручную и с приложением. Для пяти пар сначала ручной способ,
   для других пяти — приложение. Укажите запланированный порядок до запуска.
3. Запускайте и завершайте таймер по общим определениям. Пауза предназначена
   только для оговорённых внешних прерываний; причина фиксируется. Исправление ошибки
   результата относится к работе и учитывается, включая переделку.
4. Сохраните ссылку на фактический результат каждого способа. Наблюдатель проверяет
   его правильность. Укажите действительное активное время, не больше точного
   интервала таймера, и подтвердите факт измерения. Не округляйте время вверх.
5. После десяти готовых пар экспортируйте протокол. Если старое подтверждение времени
   помечено ошибочным, используйте явное исправление с причиной: история сохраняется.
6. В мастере экономики выберите два проверенных результата на одних входах,
   этот протокол и реальные допущения с основаниями: стоимость часа, месячный объём,
   расходы, внедрение и долю использования материала. Сохраните сценарий и его PDF.

Запишите и отрицательный эффект. Не заменяйте зарплату или трудозатраты удобными
цифрами. Синтетические данные автоматических регрессий не подходят для этой проверки.
PDF экономики и конкурсная приёмка остаются незавершёнными до реальных измерений.

## Что вернуть интегратору

Имя ZIP, его хеш, ОС и модель ноутбука, протокол первого запуска, список затруднений,
экспорт десяти настоящих пар с результатами задач и сценарий экономики с основаниями.
Ключ ИИ и локальную базу с чувствительными данными в чат или git не отправляйте.
