3. ВЕРХНЯЯ ГРАНИЦА, А НЕ ЕЩЕ ОДНА СХЕМА
Построена более простая задача, которая разрешает все настоящие раскрои и может разрешать некоторые физически невозможные сочетания. Следовательно, ее верхняя граница не меньше настоящего максимума.
Переменная x(part, remnant) означает назначение совместимой детали на остаток. Каждая деталь назначается не более одного раза. Материал, дефект/премиум и индивидуальные габариты учитываются до создания переменных.
Для некалёного стекла после 5 мм обрези рабочий прямоугольник (W-10)*(H-10). Увеличиваем каждую деталь справа и снизу на 3 мм, а рабочий прямоугольник на 3 мм по каждой оси: детали (w+3)*(h+3), контейнер (W-7)*(H-7). При любом допустимом раскрое такие увеличенные прямоугольники не пересекаются, поэтому сумма их площадей не превышает площадь контейнера. Это необходимое, но не достаточное условие геометрической укладки.
Для каждой пары деталей проверены обе ориентации и возможность расположить их рядом по X либо Y с зазором 3 мм. Если ни один вариант не возможен, вместе их назначать нельзя. Для максимальных клик такого графа несовместимости добавлено sum(x)<=1.
Эта MIP-релаксация решалась HiGHS через scipy.optimize.milp. Цель отрицательная площадь (минимизация). Поэтому использован именно -mip_dual_bound: он дает верхнюю границу площади. Нельзя использовать -fun (incumbent релаксации) как верхнюю границу при остановке по времени. В нескольких материалах поиск остановлен по 15-секундному лимиту; верхняя граница при этом остается допустимой с обычными численными допусками solver.
Границы м²: clear-4 <=30,6641; clear-6 <=28,14032; clear-8 <=18,8391; grey-8 <=4,2251; bronze-8 <=6,2701; mirror-4 <=26,0489. Плюс точное калёное matching 1,18 м².
Итого <=115,36762 м² / 187,8691 м² = 61,4086% на конкретном открытом наборе.
Итак, истинный максимум открытого набора находится в интервале [58,9523%; 61,4086%] по проведенным расчетам. Мы НЕ доказали оптимальность найденной схемы. Нулевой MIP gap в patterns_summary.json означает оптимум только внутри сгенерированного пула схем. Для полного пространства раскроя это не сертификат оптимальности.
65% недостижимы на этих открытых данных в исследованной модели правил; это повод уточнить у организаторов, как интерпретировать ориентир из PDF. Ничего о верхней границе еще не выданного закрытого набора это не говорит.

4. РЕКОМЕНДУЕМАЯ АРХИТЕКТУРА ОПТИМИЗАТОРА
Разделение по material_id. Для калёного стекла точное maximum-weight bipartite matching. Для обычного: портфель Guillotine/MaxRects -> пул схем -> set-packing MIP -> локальная перепаковка и генерация новых схем с учетом ценности дефицитных деталей. CP-SAT как точный локальный улучшатель для сложных групп и источник границ. Сохранять лучшее валидное решение после каждого улучшения; остановка по времени возвращает его.
Цель соревнования: максимальная площадь, не число деталей и не визуальная плотность отдельно взятого остатка. Приоритет денежной ценности в эвристике может ухудшать coverage. В точном разложении по материалам разные материалы независимы, цена за м² внутри материала постоянна, поэтому оптимизация площади каждой группы одновременно максимизирует деньги по формуле валидатора. При появлении общих ограничений производства/продаж это свойство перестает быть гарантированным.
Вторичные цели после сохранения максимальной площади: меньше операций/остатков, старые остатки, сохранение больших полезных кусков, возможность продажи. Не добавлять необоснованные веса, которые снижают главный score.
Выход каждой стадии проверять неизмененным официальным валидатором плюс собственным строгим валидатором. Полный список всех part_id, для непокрытых NEW, rot только 0/1, целые координаты, никакого использования слабостей int(float(...)).

5. ТЕХНОЛОГИЧЕСКИЕ И ПРОДУКТОВЫЕ РИСКИ
Официальный валидатор проверяет геометрию прямоугольников, но НЕ доказывает последовательность реальных резов. Guillotine-схема хранит дерево последовательных сквозных разрезов; произвольная MaxRects-схема не обязана его иметь. В интерфейсе нужно честно различать геометрически допустимую схему и технологически подтвержденную, а необходимость гильотинного ограничения уточнить у KSM/организаторов. Не выдавать произвольную упаковку за готовое задание станку.
Признак дефекта только бинарный, без расположения и размеров. По кейсу обычные детали можно класть на дефектный остаток. Для цеха этого недостаточно: нужны геометрия дефекта/осмотр и правила допуска.
Калёное стекло никогда не режется; совпадение размеров ±2 мм, допускается поворот, только одна деталь. Отступ 5 мм не применяется к точному использованию калёного целиком.
NEW по формату не требует раскладки на новом листе. Не заявлять, что система уже оптимизирует закупку целых листов.
Статусы склада available/reserved/consumed/sold, версия оптимизационного прогона, запрет двойного резервирования. После фактического реза остатки-потомки создавать только из подтвержденной схемы/замера. Для sale_cards брать исходные остатки, не использованные в текущем solution.csv; не подменять их выдуманными фрагментами.
Пример solution_example.csv — только формат, он не является валидным готовым решением этого набора.
Windows: оригинальный validate.py без UTF-8 режима упал при печати символа м² в cp1251. Запуск python -X utf8 устраняет проблему без изменения официального файла; в приложении лучше вызывать check() и форматировать вывод самим.
