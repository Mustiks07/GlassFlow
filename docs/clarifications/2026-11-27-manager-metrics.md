# Уточнение организаторов: экран проверки менеджеров

Источник: ответ организаторов из Telegram, переданный пользователем в чате 27 ноября 2026 года. Ссылка на исходное сообщение не предоставлена; отдельная проверка в Telegram не проводилась. Это уточнение требований кейса, не результат работы агента.

## Подтвержденные определения

По выбранным строкам заявок конкретного менеджера:

1. **Доля вернувшихся клиентов** = число заявок с `вернулся_за_60_дней = 1` / число заявок менеджера. Единица наблюдения — заявка. Не группировать по `client_id` для основного показателя.
2. **Средний чек** = среднее арифметическое `сумма_тг` только по строкам с `продано = 1`.
3. **Среднее время ответа** = среднее арифметическое `ответ_через_мин` по всем заявкам менеджера.

Это совпадает с разделом аналитики в утвержденном ТЗ. PDF/TXT ТЗ не переписываются. Альтернативные показатели (доля уникальных клиентов, средняя сумма всех заявок) можно показывать только под другими названиями; они не заменяют основной конкурсный показатель.

## Что проверить владельцам

- **GPT Pro Мустафы:** применить эти формулы в сервисе аналитики, API, CSV/PDF и числах демонстрации. Зафиксировать числители, знаменатели, applied filters и snapshot; не использовать prediction как наблюденный возврат.
- **Клауд первый Ильяса:** основные карточки показывают указанные метрики; tooltip доли возвратов явно говорит «заявки с возвратом / все заявки менеджера». В среднем чеке указать «по проданным заявкам».
- **Финальный интегратор:** проверить T45/T46 и фактический экран M1–M5, согласованность UI/API/документов на одном наборе. Номер теста не заменяет проверку формулы.

На оригинальном открытом наборе значения заполнены. Проектное правило ТЗ для пользовательских неполных данных остается отдельным: показывать полноту, а не молча считать пропуски нулем. Без фактической метки возврата (например, в закрытом наборе) показатель недоступен. При отсутствии продаж средний чек — `null` / «Нет продаж», не ноль. Эти граничные правила не приписываются приведенному ответу организаторов.

## Контрольный пример для регрессии

Все три строки относятся к M1:

| app_id | client_id | сумма_тг | продано | вернулся_за_60_дней | ответ_через_мин |
|---|---|---:|---:|---:|---:|
| A | C1 | 10000 | 1 | 1 | 10 |
| B | C1 | 90000 | 0 | 0 | 30 |
| C | C2 | 20000 | 1 | 1 | 20 |

Ожидается: доля возвратов **2/3 = 66,67%**, средний чек **15000 ₸**, среднее время **20 минут**. Ошибочная группировка по уникальным клиентам дала бы 100%; ошибочное усреднение чека по всем заявкам дало бы 40000 ₸. Добавить проверки фильтра менеджера, отсутствия продаж и отсутствующей метки возврата.
