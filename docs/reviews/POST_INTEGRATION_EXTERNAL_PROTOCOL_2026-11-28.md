Фаза1, база5648852,28 ноября2026. Это исполнимый протокол, **не PASS** чистой Windows, gateway или человеческих трудозамеров. Дата/участники/машины/ссылки заполняются только после действия. Старый EXE3f83310 и его ZIP остаются доступными; новый пакет имеет отдельное имя и manifest.

## Чистая Windows11

Участники: новый оператор и наблюдатель; автор не объясняет маршрут во время измеряемой попытки. Машина — новый Windows11 snapshot/компьютер без установленных Python/Node/Docker и исходного checkout. Установленные инструменты, Windows App Execution Aliases и PATH проверяются раздельно: наличие Store alias python.exe не доказывает установленный Python. Командная оболочка Windows разрешена, dev runtime не устанавливается.

1. Зафиксировать Windows edition/build,CPU/RAM,масштаб экрана, браузер и обезличенный machine_id. Не публиковать серийный номер/личное имя пользователя. Сохранить список проверенных условий чистоты.
2. Получить именно версионный ZIP и manifest. Проверить `Get-FileHash -Algorithm SHA256 <zip>` против опубликованного manifest; записать guest URL/download status и время окончания загрузки отдельно от запуска.
3. Включить непрерывную запись. Старт критерия≤5 минут — начало распаковки подготовленного ZIP. Оператор распаковывает всю папку, читает README и запускает GUI EXE; автор не подсказывает. Отдельные метки: unzip_start/unzip_end,exe_launch,ready,first_core_route_completed.
4. Не отключать защиту/SmartScreen/антивирус и не обходить TLS предупреждения. Любой блокирующий prompt фиксируется как наблюдаемый blocker, а не исключается из времени. Человеческое решение не подменяется автоматической «приёмкой».
5. Через видимый UI импортировать неизменённый открытый пакет, проверить counts/hashes, создать workspace. Выполнить реальный запрос, цену, подбор с местом, подтверждение, резерв, проверку склада и передачу. Не заявлять физическую резку стекла: actual-use — запись оператора о проверенном исполнении.
6. Второй независимый клиент пытается резервировать тот же кусок: один успех, другой409. Устаревший замер/бирка не разрешают резерв или расход. Повтор подтверждения с новым ключом не создаёт второй расход.
7. Создать backup при работающем приложении, штатно закрыть, перезапустить. Проверить факты, ledger и файл CSV. Сделать новую отличающуюся запись, восстановить backup штатным механизмом/restart и убедиться, что позднейшая запись отсутствует, предыдущие факты и C2 consumption сохранены.
8. Прервать именно проверяемый EXE во время настоящего worker job; restart должен показать interrupted и сохранённый валидный incumbent. Повтор не дублирует принятую работу. Проверить singleton, новый свободный порт и отсутствие рекурсивного spawn.
9. Повторить основной маршрут при1366×768,1920×1080,125%, клавиатурой и с длинными русскими полями. Снять саму сумму/статусы/таблицу схемы; наличие PNG без просмотра не PASS.
10. Экспортировать и скачать фактические пять CSV одного run, прочитать UTF8 без BOM/точные колонки, выполнить неизменённые validate/selfcheck отдельно от runtime. Сохранить exit codes/stdout/stderr/hashes. Закрытые баллы без KEY остаются N/A.

Вывод: старт≤5 минут и повторный старт≤30 секунд проверяются по настоящей записи. VM с dev tools или машина автора не заменяет этот сценарий. Формат evidence: machine.json,protocol-events.csv,screen recording,actual CSV/manifest,backup/recovery report,observer notes и failed attempts.

## Реальный gateway и ограниченная live AI-проверка

Требуются предоставленные/разрешённые endpoint и model_id, действующий HTTPS без обхода проверки, серверный provider key, ограниченный отзывной judge token, бюджет и независимый новый клиент. Ни секрет, ни Authorization/Cookie не попадают в JSON-отчёт, браузерный код, EXE, URL query или git. Все запросы используют учебные/искусственные испытательные данные, не данные настоящих клиентов KSM. Никаких сообщений покупателям.

1. Сначала проверка конфигурации: фактический provider/model, схема tool calls, free_only либо явное разрешение указанного платного/предоплаченного профиля. Никакого автоматического paid fallback. Протокол первого разрешённого испытания root ограничивает1млн tokens; evaluator не меняет бюджет или профиль сам.
2. Зафиксировать source SHA,полный безопасный config hash, KB/input/prompt/tools/schema/verifier versions и frozen exam hash. Ранее раскрытые кейсы помечаются regression. Независимые остаются отдельной выборкой; после использования не называются новым holdout.
3. Убедиться, что API умеет `execution_mode=model_first` и точное происхождение model/deterministic/cache/fallback/reuse с selected-model attempts. Main5648852 этого не даёт: baseline live через API BLOCKED. `allow_ai=true` само по себе не включает модель для распознанного запроса.
4. На изолированном клиенте проверить invalid token401/403,expiry и отзыв активного токена. Проверить отсутствие provider key в local app/EXE/network responses. Новая машина получает только ограниченный judge token.
5. Измерить настоящий cold start после остановки/простоя и минимум30 настоящих turns; queue,model call и end-to-end latency хранить отдельно. p95 считать из полного набора, не из удачных ответов или только последнего tool call. Локальный p95 не называется модельным.
6. Запустить frozen независимые запросы; критические повторить3 раза реальными вызовами. Правильность, применимость цены/единицы/количества, полнота, выдуманные обещания, лишние отказы/уточнения и latency проверяются отдельно. Cache/deterministic/fallback не увеличивают accuracy выбранной модели. Verifier-rejected ответ — не успешный model answer, даже если fallback вернул правильную цену.
7. Учесть реальное usage provider и ledger; unknown tokens/cost остаются unknown. Не обещать жёсткий бюджет по неточному локальному подсчёту. При приближении к разрешённому cap прекратить новые вызовы, сохранив принятые результаты; не включать другую платную модель. 429/timeout/quota оформляются как provider outcomes и partial/blocked, а не «правильные ответы».
8. Независимо вручную просмотреть весь набор коммерческих ошибок и критические ответы. Автоматический rubric не доказывает полную семантику произвольного русского текста. Приёмка требует≥95% правильных действий/ответов,0 неподтверждённых коммерческих утверждений и выполненных критических повторов; отсутствие вызовов/квоты/ручной проверки не PASS.
9. После теста отозвать тестовый token, подтвердить отказ нового запроса, сохранить безопасный отчёт. Активный секрет не вставлять в отчёт или сообщение.

## Минимум10 настоящих пар LaborStudy/U07

Файл `tests/post_review/human_tasks_v1.json` — задания и пустой протокол. В нём нет сгенерированных измерений. Оператор выполняет настоящую работу на одном и том же учебном входе сначала manual либо app согласно counterbalanced order. Знакомство/обучение проходит на отдельной тренировочной задаче и не включается в пару.

Для каждой пары: task_id,pair_id,canonical input hash, dataset/KB/stock versions, operator, observer, одинаковые start/end definitions, method,planned_order,start/pause/resume/finish UTC events,result_ref,error_count,rework,человеческое active_seconds attestation. Не использовать «ответ_через_мин» исторической CRM как активный труд. Ошибки и повторные попытки не удаляются.

Старт — оператор увидел полный исходный запрос и получил доступ к заданным источникам. Конец — получен корректный результат **или** корректно оформлено следующее действие/передача менеджеру для неизвестного. Время ожидания клиента не добавляется как работа; системное elapsed измеряется программой, активный труд подтверждает человек. Паузы/перерывы сохраняются; rework — описательная часть активного времени, не второй слагаемый.

1. Наблюдатель проверяет одинаковый input hash manual/app, источник и роль операции. Разные размеры/прайс/исходный резерв означают новую пару, не «тот же тест».
2. Во время выполнения человек пользуется реальными источниками и приложением; manual метод — каталог/таблица/калькулятор без GlassFlow. Оператору не выдаются ожидаемые ответы examiner.
3. По окончании человек явно подтверждает active_seconds; отсутствие подтверждения, прерывание или несовпавшие hash блокируют final export. Программные и synthetic test intervals не помечаются real human.
4. Получить минимум10 разных завершённых пар. Половина manual_first,половина app_first. Отрицательное manual−app сохраняется; нельзя отбрасывать неудобные или медленные задачи.
5. Сформировать LaborStudy существующего U07 через настоящий API, открыть отдельные пары из итоговой цифры. Сверить сумму/медиану/разброс и input/result references. Учётный actual material value, прирост к baseline, продажи и прибыль не суммируются как один эффект.
6. Только после достаточных реальных пар создавать финальный economics.pdf. Если людей/результатов нет, итог измеренного эффекта NOT_RUN; сценарный preview явно synthetic/assumption и не подменяет предоставленный финальный материал.

## Реестр организаций и финальные материалы

T47 требует больше HTTP200: точное имя, город, фактический профиль, уникальность юр./публичной организации, категория, source_url/date и обоснованное применение. Минимум50 разных организаций,≥30 Астана,≥5 категорий. HTTP/TLS error сохраняется, сертификаты не отключаются. Размерные допущения и предполагаемая применимость отдельно от подтверждённой деятельности; интерес/покупка никогда не предполагаются.

Для каждой из5 карточек проверить актуальные исходный кусок/версию/план/registry и3 разных BuyerMatch, whole/free constraints, фактическую цену30–70% эквивалента после округления. Смена evidence или резерва требует recheck. Недостаток evidence в складе не исправляется solver.

Итоговый README/CSV/PDF/слайды/приложение открывает проверяющий на том же source/run/package. Числа и версии сверяются с manifest. Существующая C1 презентация с placeholders остаётся draft до согласованного обновления. Drive/guest availability, официальные сроки29 ноября, регистрация/явка и права — отдельные действия команды, не автоматический PASS из наличия checklist.
